# TIM.EXE 1.00 - The Incredible Machine

`reconstruct/v1.00`, beside 1.11's `reconstruct/v1.11` (`docs/v1.11.md`);
what both share is `docs/executable.md`. This is what is known about 1.00,
the executable The Incredible Machine shipped with. Its files go in
`reconstruct/v1.00/game/`, untracked - supply your own. Its recovered image
is `out/v1.00/TIM.img`, and the tools work on it with `TIM_VERSION=1.00`.

## The file

`TIM.EXE`, 111,951 bytes, packed with **LZEXE 0.91** - the tag `LZ91` at
offset 0x1C of the header, a 32-byte header, zero relocations, entry
`1aa0:000e`. The game probes 87 levels (`L1.LEV`..`L87.LEV`).

## Recovering the image: `tools/unlzexe.py`

The stub is **run**, under the emulator, not reimplemented. It relocates
itself upward, decompresses, and hands control back down; the stop rule is the
first instruction to execute below the stub's own entry, which happens after
**1,528,688 instructions** and lands on `0000:0000`.

The **relocation table is measured, not decoded**: the stub is run twice, at
load segments 0x0110 and 0x0510, and the two images compared. A word differing
by exactly the segment delta is a relocation. Every other byte is identical -
that is checked, and a failure would mean the recovery is not deterministic.

| | |
| --- | --- |
| image | 214,512 bytes (0x345f paragraphs) |
| entry | `0000:0000` |
| stack | `3389:0080` |
| relocations | 2,327 |

**Proven, not assumed.** `tools/verify_unpack.py` loads the emitted EXE and
compares it against what the stub itself produced: all 214,512 bytes identical,
and CS, IP, SS and SP all equal. An unpack that is subtly wrong looks like a
hundred transcription bugs later, so this is a gate, not a formality.

## What built it

Borland C++ 3.0 for the game's own modules, options per module; **Borland
C++ 2.0** for the older shared ones (the graphics and file loaders, the
small utilities); **Turbo C++ 1.01** for `atan2_long`; TASM for the assembly
modules and the C ones with inline `asm`. The sound library is 3.0's, its C
compiled into one segment, 2619, where its module boundaries had to be
inferred. Each file's `JUDGE:` markers say which, and `docs/executable.md`
how it was measured.

## The copy protection

The shipped 1.00 is cracked in **one byte**. `copy_protect_screen`'s wait
loop is entered on the wrong side: after `[bp-0x12]` is cleared the routine
jumps to 0x0eddd, which *sets* it to 1, and 0x0ede2 leaves when it is not
zero - so the screen is drawn and the routine returns without ever polling,
and any answer passes.

    e9 66 01   jmp 0x0ede2    the loop's test, where a Borland `while` enters
    e9 61 01   jmp 0x0eddd    `done = 1`, and the loop never runs

The byte is 0x0ec7a. `tools/uncrack.py`'s `CRACKS` holds it, and the judge and
`tools/link.py` put the original byte back and build with
`TIM_COPY_PROTECTION`; `--cracked` builds the source's default, the crack,
against the shipped bytes.

## The link

`tools/link.py` links 1.00's modules with BC++ 3.0's TLINK behind `C0M.OBJ`
against `CM.LIB`: every byte TLINK writes - 205,326 - is the original's, as
are all 2,324 relocations, the entry and the stack. **And the whole file is
the original's**: linked with TLINK's `/i`, which writes the zero-initialised
segments and the stack into the file, the cracked build packed with LZEXE 0.91
is the shipped TIM.EXE byte for byte - once its header's `minalloc` is 0x182,
not TLINK's 0. That word is the crack's: LZEXE adds 0x182 paragraphs of its
own to the input's `minalloc`, so the shipped file was packed twice - the
developer's, unpacked, patched, packed again. `link.py`'s verdict is each
build's SHA-256:

| | SHA-256 |
| --- | --- |
| protected | `ed5d15b20fad268834c584b98c5d98abc76f423a718bf636a294d5c36366f683` |
| cracked | `3e0183d8df59febe22946cf973b43eea735f1821001676eeda616041ac1160c2` |

## What differs from 1.11

`docs/v1.11.md` has it from 1.11's side: 1.11 reads `RESOURCE.CFG` as text
where 1.00 reads three binary bytes, draws the Dynamix screen where 1.00
draws Sierra's (`sierra.scr`, `sierra.pal`), carries no resource writers,
links its sound library a module to a segment, and 1.00 has 58 part kinds to
1.11's 66.
